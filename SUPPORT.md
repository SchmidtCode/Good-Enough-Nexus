# Good Enough Nexus support

Use the route that matches the problem so the report requests the right evidence.

- **Bug:** [Bug Report](https://github.com/SchmidtCode/Good-Enough-Nexus/issues/new?template=01-bug-report.yml)
- **Performance or stutter:** [Performance / Stutter Report](https://github.com/SchmidtCode/Good-Enough-Nexus/issues/new?template=02-performance-stutter-report.yml)
- **Sync or multiplayer:** [Sync / Multiplayer Report](https://github.com/SchmidtCode/Good-Enough-Nexus/issues/new?template=03-sync-multiplayer-report.yml)
- **Security:** [Report a vulnerability privately](https://github.com/SchmidtCode/Good-Enough-Nexus/security/advisories/new). Do not disclose vulnerability details in a public issue.

Feature requests are deferred while the 1.96 compatibility line is maintained. Existing feature discussions may remain open, but new feature work is not currently the support priority.

Before troubleshooting Nexus, disable Project Ebonhold Enhanced. That addon is
unmaintained for recent Project Ebonhold patches and is incompatible with
current Nexus builds. It can interfere with server-backed loadouts, wishlist
creation, and automation.

For incorrect Progress, Still Needed, or To Shed values, check these before
opening an issue:

1. Open Character Progression, then Echoes.
2. Confirm the normal Ebonhold loadout menu shows the Saved Build you are using.
3. Confirm the blue **Nexus HUD target** menu points at the intended wishlist.
4. At level 80, save over the active Ebonhold Saved Build after an orb upgrade.
5. If you just completed a level 1 to 80 run, switch away and back once so
   Ebonhold refreshes the active loadout.

Before submitting a report, search existing issues, confirm the exact Good Enough Nexus build, preserve SavedVariables, and capture the diagnostics requested by the selected form.
